RBP User Manual

Version 1.13

RBP (Rapid Batch-process-supported Powerful tool) is a command-line tool for GWAS and genomic selection (GS) on large-scale genomic data, built on the mixed linear model (MLM).

1. Introduction

Genotyping has outgrown the classical analysis pipeline. A single sequencing or imputation project can carry millions of markers on hundreds of thousands of individuals, so a genome-wide mixed model has to solve a system whose dimension is the number of individuals, repeatedly, once per variance-component iteration. The practical bottlenecks are therefore matrix size (memory) and the number of linear solves (time), not the statistical model itself.

RBP is built around those two bottlenecks.

What it does

  • GWAS — scan markers for association with a trait under a mixed model, with

the polygenic background absorbed by a relationship matrix.

  • GS / BLUP — estimate variance components and breeding values (random effects)

for selection, from pedigree, genotypes, or both.

Algorithmic features

Feature What it buys
AI-REML for variance componentsFast, well-tested REML, with a stopping rule on the parameter change or the gradient
Linear solvers: direct Cholesky, CG and deflated PCGA direct solve for small problems; matrix-free CG with Lanczos eigenvalue deflation for large ones
Deflation of the mixed-model operatorRemoves the extreme eigenvalues, cutting the CG iteration count by an order of magnitude on large single-step problems
Single-step (--single-step)Fits pedigree + genomic information jointly without ever forming H or H⁻¹: pedigree terms are applied through T/D operators, the genomic block through a Schur complement with a preconditioned inner CG
Chunked (out-of-core) modeGenotype/GRM blocks are streamed from disk, so the working set stays bounded for very large data
Low-rank compression (--make-compress)LD-block PC1 projection turns a high-density marker matrix into a compact predictor matrix
Precision control (--float / double)Single precision roughly halves the memory footprint
Batch mode (--batch-trait)Many traits analysed in one pass, sharing the genotype/GRM work

Implementation

C++ with Armadillo and OpenMP. OpenBLAS or Intel MKL is linked statically; the Fortran/OpenMP runtime is bundled with the binaries, so the release package runs on a bare Linux installation (see §2). The rbp launcher selects the appropriate binary for the machine.

Smoke test

The bundled demo data runs the whole pipeline in about two minutes:

# the demo phenotype has the header "ID sex trait": trait = col 3, sex = col 2
./rbp --make-grm   --geno data/demo_geno --method 2 --out demo --ncpus 8
./rbp --kpca       --grm demo.GA --npc 10 --out demo --ncpus 8
./rbp --single-trait --grm demo.GA --phe data/demo_pheno.txt \
      --phe-col 3 --fix-col 2 --out demo --ncpus 8

demo.var should report a genetic variance near 0.40 and a residual near 0.59 (h² ≈ 0.41) — the demo population was simulated with h² = 0.4.

3. Input file formats

All input files are whitespace-separated text unless stated otherwise, and all column indices are 1-based (the ID column counts as column 1).

3.1 Phenotype file

A phenotype file holds one row per record and must have a header line. Its first column must be the individual ID; every other quantity used by the model — traits, fixed effects, covariates and any additional random effect — must be a column of this same file.

ID       sex   trait     herd   age    dam
100001   1     0.533     A      3.2    NA
100002   2     0.624     B      2.8    100014
100003   1    -0.053     A      4.1    NA
Parameter Meaning
--phe FILEthe phenotype file
--phe-col STRwhich column(s) hold the trait(s): --phe-col 3 for one trait, --phe-col 3,4 for several. In --batch-trait mode this selects the traits analysed in one run

Only the individuals present in the phenotype file contribute records; individuals without a record may still appear in the relationship matrix (they then receive an EBV but no residual).

3.2 Fixed effects and covariates

Both live in the phenotype file as extra columns; the difference is how they are treated:

  • Fixed effects are categorical — sex, herd, batch, year. One coefficient per

level (the program builds the design matrix).

  • Covariates are continuous — age, weight, inbreeding coefficient. One

regression coefficient each.

Parameter Meaning Example
--fix-col STRcategorical fixed-effect column(s), 1-based, comma-separated--fix-col 2 (sex) or --fix-col 2,4 (sex + herd)
--cov-col STRcontinuous covariate column(s)--cov-col 5 (age)

A model statement spelled out in one line reads: *trait = column 3, fixed effects are sex (column 2) and herd (column 4), age (column 5) enters as a covariate* → --phe-col 3 --fix-col 2,4 --cov-col 5.

3.3 Additional random effects

Random effects other than the genetic one (a permanent environment, a litter effect, a maternal genetic effect) are handled the same way: the factor whose levels are the random-effect levels must be a column of the phenotype file, and each such column is declared with --rand-col.

Parameter Meaning
--rand-col STRcolumn(s) holding additional random effects, comma-separated; --single-trait only
--rand-cov LISTthe covariance structure of each additional random effect, space-separated and in the same order as --rand-col

--rand-cov accepts three kinds of entry:

Entry Meaning
1identity — the levels are independent and identically distributed (i.i.d.)
a file ending in .pedthe levels are linked by a pedigree relationship matrix (e.g. a maternal genetic effect)
a matrix prefixthe levels are linked by a user-supplied covariance matrix, stored in the same layout as a genetic relationship matrix (a .bin plus a matching .id; see §3.7)

A text file listing one entry per line may be given instead of an inline list.

# i.i.d. litter effect (column 6) + maternal genetic effect from the pedigree (column 7)
./rbp --single-trait --grm G.GA --phe pheno.txt --phe-col 3 --fix-col 2 \
      --rand-col 6,7 --rand-cov 1 data/demo_pedigree.ped --out demo

3.4 Pedigree file

Three columns, with a header line (a header is recognised and skipped — see below), one row per individual, unknown parents coded as 0:

ID     Sire   Dam
63212  0      0
76841  0      0
100001 63212  76841
Parameter Meaning
--pedigree FILEpedigree, used by --single-step and --make-hmatrix

The parser detects a header line automatically when the first token is one of the common header labels (ID, id, IND, Animal, Individual, 个体号, …), so a pedigree without a header is also accepted. Individuals in the genotype file must all be present in the pedigree with the same IDs.

3.5 Genotype file

Only the PLINK binary format is supported: a .bed / .bim / .fam triple, specified by its prefix (--geno PREFIX, with or without the .bed suffix).

ID rule. The second column of the .fam file (the IID) is the ID used throughout RBP. It must be identical to the ID column of the phenotype file and of the pedigree file — otherwise the same animal is treated as two different individuals.

Parameter Meaning
--geno FILEgenotype prefix
--geno-ind STRkeep only these individuals: comma-separated 1-based indices, or a file with one index per line
--geno-snp STRkeep only these markers, same syntax
 
--geno data/demo_geno
--geno-ind 1,3,5,100      --geno-ind keep_ids.txt
--geno-snp 1,2,3,500      --geno-snp snp_list.txt

*Smart parsing*: if the argument is an existing file it is read as a list, otherwise it is parsed as a comma-separated index list. Indices refer to the .fam / .bim order, 1-based.

3.6 SNP weight file

A single column of numbers, no header, one weight per marker of the selected marker set (i.e. after --geno-snp).

Parameter Meaning
--weight FILEper-SNP weights, used by --make-grm and --make-compress

Rules enforced by the program:

  • the number of weights must equal the number of selected markers, otherwise

SNP weights vector length must match the number of selected SNPs.

  • weights must be non-negative; non-positive weights are rejected by the

compression path (SNP weights cannot contain negative values.)

  • if the file is omitted, all markers receive weight 1.
./rbp --make-grm --geno geno --weight snp_weights.txt --out G

3.7 Genetic relationship and predictor matrices

Everything a module reads through --grm is a binary matrix plus an ID file, identified by a shared prefix:

File Content
<prefix>.binthe matrix, binary. Symmetric matrices are stored as the lower triangle (n(n+1)/2 values); predictor matrices as the full n × k block
<prefix>.idone ID per line, giving the row/column order (rows for predictor matrices)
<prefix>.colonly for the non-symmetric predictor matrices — see below

Two families exist.

(a) Symmetric relationship matrices — written by --make-grm / --make-hmatrix:

Prefix Matrix Intended use
.GAgenomic additive (Yang or VanRaden)BLUP, GWAS
.GDgenomic dominancedominance models
.HA, .HDpedigree-informed H (G blended with A22)*see the note below*

Recommendation. Do not feed .HA / .HD to --single-trait for a single-step analysis. Build them only if a file-based H matrix is really needed; the --single-step module works directly from the pedigree plus the GRM and is markedly faster and lighter on memory.

(b) Non-symmetric predictor matrices — written by --make-compress:

Prefix Matrix .col content Intended use
.Zstandardised genotypes, with Z Zᵀ = Gmarker names, one per linechip-level data (tens of thousands of markers)
.compressLD-block PC1-compressed marker matrixLD blocks, one per line as chrom:start-endlarge-scale sequencing / imputed data (millions of markers)

Because these matrices are rectangular, the .col file records what the columns mean: marker identity for .Z, and the genomic interval of each block for .compress. Both are accepted wherever a GRM prefix is accepted.

4.1 Global parameters

These apply to every module.

Parameter Meaning Default
--out PREFIXprefix of all output filesrbp
--ncpus Nnumber of CPU threads1
--floatsingle precision (float) to save memoryoff (double)
--chunkforce the out-of-core (chunked) path for very large dataoff
--quietsuppress console output (the .log file is still written)off

Three rules worth memorising:

1. --float must be consistent. If a GRM is built with --float, every module that reads it must also run with --float — mixing float and double binaries raises a data-type error. 2. --chunk is not available for --batch-trait. 3. PEV, the standard GWAS test and the Cholesky solver require a full, non-chunked KINSHIP GRM — otherwise the run stops with PEV, standard test and Cholesky solver require non-chunked GRM. Remove the --chunk parameter.

--make-hmatrix

Builds the file-based single-step matrix from a pedigree plus one or two GRMs, using the blending G_w = (1 - w) G + w A22, and writes it out.

--trans-grm

Streams an existing GRM binary between precisions, without going back to the genotypes.

./rbp --trans-grm --grm demo.GA --float --out demo_f    # double -> float

--out must differ from the input prefix (the program refuses to overwrite the input). The module works on the plain <prefix>.bin/.id/.col triple, so give the full prefix (demo.GA, not demo).

4.3 Principal component analysis (--kpca)

Computes the leading principal components of the relationship matrix with a Lanczos iteration — for describing population structure, as covariates in a model, or for dimensionality reduction before clustering.

Parameter Meaning Default
--grm LISTGRM prefixrequired
--npc Nnumber of leading PCs10
--tol VALLanczos convergence tolerance1e-6

Output: <out>.eigval (eigenvalues, descending), <out>.eigvec (the corresponding eigenvectors, one column per PC).

./rbp --kpca --grm demo.GA --npc 20 --out pca --ncpus 16

4.4 BLUP (--single-trait)

Fits the mixed model

y = Xb + Zu + e

by AI-REML: variance components are estimated by average-information REML, then fixed effects, random effects (EBVs) and — on request — their prediction error variance are computed. With --gwas the same fitted model powers a marker scan (§4.8).

Solvers

The mixed-model equations inside every AI-REML iteration can be solved in three ways; --solver selects between them, while deflation is a property of the CG path.

Mode How to select Characteristics When to use
Cholesky--solver CholeskyDirect inversion of the mixed-model operator; most accurate per solve, but needs the full, non-chunked relationship matrix and O(n²) memorySmall to medium data sets, or when the operator must be inverted anyway (PEV by inversion)
CG--solver CG (default)Matrix-free preconditioned conjugate gradients; memory proportional to the data, works chunkedLarge data; the default choice
DPCG--solver CG with deflation (the default)CG with Lanczos eigenvalue deflation: --lanczos-m largest and --lanczos-lm smallest eigenpairs are removed, so the deflated operator is far better conditioned and the CG converges in many fewer iterationsThe default and the recommended setting for large single-step / large-GRM problems; --no-deflation falls back to plain CG

The repeatability model (--repeat) always uses the CG path.

Parameters

Parameter Meaning Default
--grm LISTrelationship matrix/matrices (§3.7); several prefixes give several variance componentsrequired
--phe, --phe-col, --fix-col, --cov-col, --rand-col, --rand-covdata and model (§3.1–3.3)—
--solver METHODCG or CholeskyCG
--no-deflationdisable Lanczos deflation (plain CG)off
--lanczos-m Nnumber of largest eigenvalues deflated87
--lanczos-lm Nnumber of smallest eigenvalues deflated13
--criterion NAI-REML stopping rule: 0 = either, 1 = relative error, 2 = gradient0
--maxit Nmaximum AI-REML iterations30
--tol VALAI-REML convergence tolerance1e-5
--cg-maxit Nmaximum CG iterations per solve500
--cg-tol VALCG convergence tolerance1e-6
--mominitialise variance components with MoM-RHEoff
--pevoutput PEV and reliability for the random effects (§4.7)off
--repeatrepeated-records model (adds a permanent-environment component)off
--seed Nrandom seed for the stochastic trace estimates6666
--gwas, --test, --num-ranvec, --re-gamma-size, --re-est-gammamarker scan (§4.8)—

Examples

(1) One genetic random effect — the standard genomic BLUP:

./rbp --make-grm --geno geno --method 2 --out G --ncpus 32
./rbp --single-trait --grm G.GA --phe pheno.txt \
      --phe-col 3 --fix-col 2 --out gs --ncpus 32

(2) Several genetic random effects — additive and dominance together; each --grm prefix contributes its own variance component:

./rbp --make-grm --geno geno --method 2 --out A --ncpus 32
./rbp --make-grm --geno geno --method 3 --out D --ncpus 32
./rbp --single-trait --grm A.GA D.GD --phe pheno.txt \
      --phe-col 3 --fix-col 2 --out ad --ncpus 32

(3) Repeatability model — repeated records per individual; a permanent environment is added, and the CG path is used automatically:

./rbp --single-trait --grm G.GA --phe records.txt \
      --phe-col 3 --fix-col 2 --repeat --out rep --ncpus 32
# records.txt holds one row per record, several rows per individual

(4) Maternal genetic effect — an extra random effect whose levels are related through the pedigree; the maternal-effect column (here 7) and the pedigree are given separately:

./rbp --single-trait --grm G.GA --phe pheno.txt \
      --phe-col 3 --fix-col 2 \
      --rand-col 7 --rand-cov data/demo_pedigree.ped \
      --out mat --ncpus 32

The same mechanism covers i.i.d. effects (litter, batch, technician): --rand-col 6 --rand-cov 1. A user-supplied covariance matrix can be passed as a .bin/.id prefix instead of .ped — see §3.3.

Output

<out>.log, <out>.var, <out>.rand, <out>.beta, <out>.anova (+ <out>.mlm with --gwas); see Appendix A.

4.5 Single-step BLUP (--single-step)

Fits the single-step model, in which the genetic random effect follows N(0, H σ²_u), with H combining pedigree (A) and genomic (G) information through the standard blending of G with A22.

When pedigree information exists, this module is strongly recommended over --single-trait with a pre-built .HA matrix.

How it computes

The module never forms H (or H⁻¹):

  • the pedigree part is applied through the sparse T⁻¹ and D⁻¹ operators of

A⁻¹ = (T⁻¹)ᵀ D⁻¹ T⁻¹, at O(n) cost per application;

  • the genomic block is handled by a Schur complement whose inner system

A¹¹ x = b is solved by a preconditioned CG in the non-genotyped ordering;

  • the outermost system is solved by CG with Lanczos deflation, so the extreme

eigenvalues of the mixed-model operator are removed.

The advantages are memory (no dense H, no H⁻¹) and speed (fewer CG iterations per AI-REML step, with all operators sparse or O(n)).

Parameter Meaning Default
--pedigree FILE3-column pedigree (§3.4)required
--grm LIST.GA, .GD or .compress prefixes; an empty list gives a pedigree-only (ABLUP) analysisempty
--phe, --phe-col, --fix-col, --cov-col, --rand-col, --rand-covdata and model (§3.1–3.3)—
--w VALUEblending weight of A22 in G_w0.05
--decoupledecouple H into A + ΣΔᵢ and fit a separate variance component per genomic termoff
--a22-size-limit Nuse a dense A22⁻¹ when n₂ ≤ N, a sparse Cholesky otherwise30000
--maxit, --tolAI-REML iterations and tolerance30, 1e-5
--cg-maxit, --cg-tolCG iterations and tolerance500, 1e-6
--lanczos-m, --lanczos-lmdeflated largest / smallest eigenpairs87, 13
--no-deflationplain CG instead of deflated PCGoff
 
./rbp --make-grm --geno geno --method 2 --out G.GA --ncpus 32
./rbp --single-step --pedigree ped.txt --grm G.GA \
      --phe pheno.txt --phe-col 3 --fix-col 2 \
      --a22-size-limit 20000 --w 0.05 --out ss --ncpus 32

Output: <out>.log, <out>.var, <out>.rand, <out>.beta, <out>.anova. With --gwas the scan runs in genotype space (SSGWAS) — see §4.8.

[TBC] Guidance for choosing --lanczos-m / --lanczos-lm and --a22-size-limit as a function of the model size.

4.6 Batch BLUP (--batch-trait)

Analyses many traits in one pass. It is a batch implementation, *not* a multivariate (multi-trait) model: each trait is fitted independently, sharing the genotype/GRM preparation and all I/O.

Aspect Behaviour

Missing valuesphenotypes may be missing — records are kept only where the trait is observed, and the likelihood is evaluated on that subset. Covariates must be present for the retained records [TBC: confirm the covariate rule]
Variance componentsestimated by DFREML (the program prints [ DFREML Running ]); the exact GWAS test internally runs AI-REML per phenotype

Parameter Meaning Default
--grm LIST, --geno, --phe, --phe-col, --fix-col, --cov-coldata and model (§3)—

Output: <out>.log, <out>.batchmlm (GWAS results for all traits), <out>.batchSummary (per-trait summary), plus the per-trait .var, .rand, .beta, .anova files.

4.7 PEV and reliability

For a BLUP the breeding value is a prediction, and its uncertainty is described by two numbers:

  • PEV — the *prediction error variance* Var(û − u): how far the estimate is

expected to be from the true value;

  • reliability — r² = 1 − PEV / σ²_u, the fraction of the additive genetic

variance the prediction explains (1 means a perfectly predicted EBV).

Both are requested with --pev in --single-trait:

./rbp --single-trait --grm G.GA --phe pheno.txt --phe-col 3 --fix-col 2 \
      --pev --out gs --ncpus 32

Output. <out>.rand gains two columns per random effect, <effect>_PEV and <effect>_r2:

ID      G.GA      residuals   G.GA_PEV   G.GA_r2
100001  0.533099  ...         0.132      0.678

Individuals that are not levels of a given effect receive NA in that effect's columns.

Requirements and scope

  • PEV needs the projection matrix P, hence a KINSHIP-type GRM and a

non-chunked one: otherwise the run stops with PEV, standard test and Cholesky solver only support KINSHIP GRM. or ... require non-chunked GRM. Remove the --chunk parameter.

  • Only single-trait runs produce PEV. For a multi-trait run the program reports

PEV can only be calculated for single trait and continues without it, and --batch-trait does not produce PEV at all.

  • It is not available from --single-step, whose H-type kernels are not KINSHIP

matrices.

4.8 GWAS

Adding --gwas to --single-trait, --single-step or --batch-trait scans the markers under the fitted mixed model.

--gwas requires --geno as well, because marker IDs are matched against the genotype file: Genotype prefix (--geno) is required for matching IDs.

Test --single-trait --single-step (SSGWAS) --batch-trait Notes
standardyes—yesNeeds the projection matrix P ⇒ KINSHIP GRM, non-chunked, single record per individual
quasi-standardyes——Stochastic approximation; no P required; for large data where standard is too expensive
gammayesyes (the only option)yesUses the estimated gamma shape; the practical choice for SSGWAS and very large scans
exact——yesPer-phenotype iterative AI-REML scan

Recommendations: gamma as the default for large data and for single-step (it is the only test accepted there; otherwise the program stops with SSGWAS only support gamma test.); standard when the projection matrix is affordable and a classical score test is wanted; quasi-standard as a cheaper approximation of standard; exact is the batch-mode reference and the slowest.

Related parameters: --num-ranvec N (random vectors for the stochastic tests, default 100), --re-gamma-size N (SNPs used to estimate the gamma shape, default 500), --re-est-gamma (force re-estimation), --seed N (default 6666).

./rbp --single-trait --grm demo.GA --geno data/demo_geno \
      --phe data/demo_pheno.txt --phe-col 3 --fix-col 2 \
      --gwas --test standard --out scan --ncpus 32

Output: <out>.mlm, with the columns

SNP  CHR  POS  A1  A2  Freq  Effect  SE  Pvalue

--batch-trait writes <out>.batchmlm (all traits side by side) plus <out>.batchSummary.

Appendix B — Complete workflows

A. GWAS with a genomic relationship matrix

./rbp --make-grm --geno geno --method 2 --out G --ncpus 32
./rbp --single-trait --grm G.GA --geno geno --phe pheno.txt \
      --phe-col 3 --fix-col 2 --gwas --test standard --out scan --ncpus 32
# hits are in scan.mlm

B. Genomic prediction (EBVs for selection)

./rbp --make-grm --geno geno --method 2 --out G --ncpus 32
./rbp --single-trait --grm G.GA --phe pheno.txt --phe-col 3 --fix-col 2 \
      --pev --out gs --ncpus 32
# EBVs and reliabilities are in gs.rand

C. Single-step (ssGBLUP) with pedigree + genotypes

./rbp --make-grm --geno geno --method 2 --out G.GA --ncpus 32
./rbp --single-step --pedigree ped.txt --grm G.GA --phe pheno.txt \
      --phe-col 3 --fix-col 2 --a22-size-limit 20000 --out ss --ncpus 32

D. Single-step GWAS (SSGWAS)

./rbp --single-step --pedigree ped.txt --grm G.GA --geno geno \
      --phe pheno.txt --phe-col 3 --fix-col 2 \
      --gwas --test gamma --out ssgwas --ncpus 32

E. Large-scale, memory-limited run

./rbp --make-grm --geno geno --method 2 --float --chunk \
      --snp-chunk 20000 --ind-chunk 512 --out G --ncpus 64
./rbp --single-trait --grm G.GA --float --chunk \
      --phe pheno.txt --phe-col 3 --fix-col 2 --out big --ncpus 64

Appendix C — Performance and memory

  • Threads — --ncpus sets the OpenMP team size; OMP_NUM_THREADS,

OPENBLAS_NUM_THREADS and MKL_NUM_THREADS also apply.

  • Precision — --float roughly halves the working set; keep it consistent

across the whole pipeline (§4.1).

  • Chunking — --chunk streams matrix blocks instead of holding them, and is

recommended above ~50,000 genotyped individuals. It is incompatible with --batch-trait, with the Cholesky solver, with the standard test and with --pev.

  • Deflation — --lanczos-m / --lanczos-lm decide how many extreme

eigenvalues are removed from the operator. More deflation means fewer CG iterations in every AI-REML step, at the cost of one Lanczos pass in the first iteration.

  • A22 path — --a22-size-limit switches between a dense A22⁻¹ and a sparse

Cholesky for the non-genotyped block.

single-step runs with 100,000–150,000 genotyped individuals (double precision, 32 threads), peak memory stayed at 3–4 GB and the analysis converged within 5–6 AI-REML iterations.
